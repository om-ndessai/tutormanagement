# apps/mobile — the iOS and Android app

The native app for the tutoring portal: Expo SDK 57 (React Native 0.86, React 19.2.3), expo-router,
React Native Paper (Material 3). The repo-wide rules in `/CLAUDE.md` all apply. This file adds what
is particular to the app. The plan, the progress checklist and the parity tracker are in
`docs/mobile/`. Build every feature with the `mobile-architect`, `mobile-developer` and
`mobile-tester` skills.

## Expo changes every SDK. Do not trust memory

Before writing code that touches an Expo, EAS or React Native API, read the versioned docs for
**SDK 57**: https://docs.expo.dev/versions/v57.0.0/, or the index at
https://docs.expo.dev/llms.txt. Add dependencies with `npx expo install <pkg>`, never a bare
`npm install`, so versions match the SDK. Then run `npm run doctor`.

## Install and layout

- **Not an npm workspace.** Expo pins React 19.2.3 and TypeScript 6; the web app runs React
  19.3 and TypeScript 7.
  - This folder has its own `package-lock.json`. Install with `npm run mobile:install` from
    the root, or `npm install` here.
  - `@tmi/shared` is `file:../../packages/shared`, a symlink.
  - `metro.config.js` watches it, maps its `./x.js` imports to `.ts`, and resolves its bare
    imports (`zod`) from this app's `node_modules`, so there is one zod and one React.
  - `tsconfig.json` pins `zod` the same way.
- **Generated native folders.** `ios/` and `android/` are generated by `expo prebuild`
  (Continuous Native Generation) and gitignored. Never edit them by hand: configure
  `app.config.ts` and config plugins instead.
- **Variants.** `app.config.ts` builds `APP_VARIANT=development|e2e|production`. The bundle
  ids are `com.tutorportal.app(.dev|.e2e)`.
- **Directories:**
  - `src/app/`: expo-router routes only, kept thin. `(org)` needs an organization, `(org)/(tabs)`
    holds the role tabs, `(platform)` is the console, `(dev)` holds developer-only screens.
  - `src/features/<feature>/`: mirrors `apps/web/src/features/<feature>/`. Holds `api.ts`
    (copied from web, same query keys), components and screens.
  - `src/components`, `src/lib`, `src/providers`, `src/theme`: app-wide building blocks.

## Rules particular to the app

- **Talking to the server.**
  - Every request goes through `src/lib/api-client.ts`. It adds `X-Organization`, and while
    the server has sign-in off it adds `X-Dev-User`.
  - The query cache is never persisted, and it is cleared on an organization switch and on
    sign-out.
- **Money.**
  - Money is rendered only by `SessionMoney` and the finance components. No `formatCents`
    elsewhere.
  - The Tutoring tab and everything it opens pass `showMoney={false}`, which is the default.
- **SSN.**
  - It is typed only in the 1099 sheet and lives in component state.
  - Print with `Print.printAsync({ html })`. **`printToFileAsync` is banned**: it writes a PDF
    containing the SSN to disk.
- **Downloads.** CSV and ICS files go to the cache, then the share sheet, and are then deleted.
- **Colours.** Only from `useAppTheme()`. No hex outside `src/theme/`. The palettes are
  generated from `apps/web/src/index.css` by `scripts/generate-palettes.mjs`. Never edit
  `palettes.generated.ts` by hand.
- **Names.** No organization's name in code. Use `useBrand().short`.
- **System surfaces.** Notifications, Live Activities, widgets and the app-switcher snapshot
  carry no money, notes or student names.
- **testIDs.** `screen-<route>` on each screen root; `<feature>-<element>[-<id>]` elsewhere.
  Icon-only controls get an `accessibilityLabel`.

## Commands (from the repo root)

| Command | What it does |
| --- | --- |
| `npm run mobile:install` | install this app's dependencies |
| `npm run mobile:ios` / `mobile:android` | build and run on the simulator / emulator (dev variant) |
| `npm run mobile:start` | Metro only (the app is already installed) |
| `npm run mobile:typecheck` | tsc, the palette staleness check and the rules script |
| `npm run mobile:lint` / `mobile:test` | ESLint / Jest |
| `npm run mobile:export` | bundle both platforms (catches Metro errors without a native build) |
| `npm run e2e:mobile -- ios\|android\|both` | reset the local DB, then run the Maestro flows (local Worker only) |

## Running against a server

- **Locally.** `npm run db:reset && npm run dev:api` serves the Worker on :8787 with sign-in
  off.
  - The iOS simulator reaches it at `localhost`.
  - Android reaches it through `adb reverse tcp:8787 tcp:8787`, which the scripts run.
- **Developer sign-in.** Pick a seeded person. It works only while the server reports
  `auth_enabled: false`, and never in the production variant.
- **Never run tests against production or the demo Worker.**
