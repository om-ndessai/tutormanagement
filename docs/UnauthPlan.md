
 Now that the app/portal are in good shape for next level, the goal I am trying to solve is improving stickiness. The app/platform should take the users right into usability. We will use quest as the bait for that scenario. Then the nudge should be for people to sign up.For logged in users the usability of the app with one click quest start should be priority.

1. The users should not be required to authenticate to use or try features. 
2. 10 questions in each currculum category will be marked as guest questions. These questions will be only served for unauthenticated quests or assessment.
3. Instead of current home screen asking users to login, I want to indeify screen proposals where users could quickly use the features of the platform.
4. Users can with one click get into single player quest. The titles on the homescreen should be named like <Curriculum><QuestFormat>. Some of the things I am thinking could be G4T10 - grade 4 10 mins. BA3Q5 - will reflect the Beast Academy level 3 5 question quest.
5. A lot of tiles on the home screen will be greyed out with a lock symbol to indicate those can only be unlocked for authenticated users.
6. Unauthenticated users should also be nudged to say to have non repeated questions, they should authenticate / sign up.
7. Another idea could be after 1st question on the quest, a popup should appear - pause the time - and the popup should highlight benefits of signing up. Such as unlocking more quest options, ability to start a multiplayer quest, join a quest, share quest results etc.
7. Provide configurability on the platform console for platform admins to configure these parameters - what tiles are enabled for unuthenticated users etc. 
8. Home page should have a nudge for users to sign in.
9. For authenticated users, the home page should have favorite section to let them start quest with one click. If the favorite is a multiplayer, it would quickly result in second screen with quest code to join. The favorites should allow even player configuration such as in a family 4 ppl could be playing a quest regularly. In this case, there need not be a code sharing, on the quest page for each user, the quest would show for all the users to join and the quest creator could start the quest right away.
