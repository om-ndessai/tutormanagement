# Mobile build log

The `mobile-architect` skill writes a design entry here before each feature is built. Each entry
covers scope, web sources, endpoints, screens, exposure checks, testIDs, flows and risks. The
`mobile-tester` skill adds what it verified underneath. Together the entries record that every
feature was designed, built and tested by the three skills.

## 19. Sessions — drafts and 3-second autosave — design (2026-10-08)
**Scope:** the draft half of the web SessionFormDialog and the DraftsPanel. While a NEW lesson is written up (or a draft is picked back up — never an edit of a lesson on the record), the record sheet saves into the writer's own draft every `DRAFT_AUTOSAVE_INTERVAL_MS` (3 s) when there is content and a pairing and the body changed since the last save or the last failed try, never two at once: first `POST /sessions/drafts?autosave=true`, then `PATCH /sessions/drafts/:id?autosave=true` (no audit line). Before each autosave the body is `safeParse`d with the shared `sessionDraftInputSchema`; an invalid body (an SSN-shaped note, an end before the start) is not sent — its field errors show under the fields and the status says "Not autosaved yet", until the text changes. The app adds a save when it goes to the background (AppState), as a phone is put away mid-sentence. Closing the sheet (Cancel, swipe down, Android back) makes a final save and, for a new write-up that became a draft, the toast "Your write-up is kept as a draft. Pick it up from Drafts." Buttons: Save draft (explicit, audited: `useSaveDraft`; "Saved as a draft. Only you can see it." / "Draft saved."), Record session (consumes the draft with `from_draft_id`), and for a draft "Post session" (autosave first, then `POST /sessions/drafts/:id/post`; "Session recorded. Everyone concerned can see it now."). The AutosaveStatus line beside the buttons: idle "Autosaves as a draft while you write", "Saving draft…", "Draft autosaved 4:05 PM" (the organization's clock), "Not autosaved yet". The Drafts panel ("Your drafts · Only you can see it/these") on the Sessions **Tutoring** tab only (as asked; the web shows it above both tabs, and a draft carries no money either way), not while one lesson is in focus: student + "Draft" tag, day · time range · mode (· "no notes yet"), Continue, Post, Discard (confirmation "Discard this draft?" — "Keep it" / "Discard"). Left out: the unsaved-close guard (closing saves, which is the web's answer).
**Web sources:** `features/teaching/session-form-dialog.tsx` (the autosave refs, `runAutosave`, `settleAutosave`, `handleOpenChange`, `handleSaveDraft`, `handlePostDraft`, `from_draft_id`, `AutosaveStatus`), `drafts-panel.tsx`, `sessions-page.tsx` (where the panel sits).
**Endpoints:** `GET /sessions/drafts` — `useMyDrafts` (`['session-drafts']`) — anyone, own drafts only (R10); `POST /sessions/drafts[?autosave=true]` and `PATCH /sessions/drafts/:id[?autosave=true]` — `useSaveDraft` / `useAutosaveDraft` — the writer, for a pairing they may record (`assertMayWriteFor`); `DELETE /sessions/drafts/:id` — `useDiscardDraft` — author only; `POST /sessions/drafts/:id/post` — `usePostDraft` — author only; `POST /sessions` with `from_draft_id` — `useRecordSession` (the recorder's own draft only). **Screens & routes:** `(org)/record-session` gains `?draft=<id>` (title "Finish this draft"). The panel is part of the Sessions list header (`features/teaching/drafts-panel.tsx`); Continue pushes `/record-session?draft=<id>&tab=tutoring`.
**Components:** new `session-form/use-draft-autosave.ts` (the interval, the AppState save, `settle()`, `finalSave()` on unmount, status state; reads the latest body through a ref — tested with fake timers), `session-form/autosave-status.tsx`, `drafts-panel.tsx`; `formFromDraft` added to `use-session-form.ts`; `formatInstantClock(iso, tz)` added to `session-format.ts`.
