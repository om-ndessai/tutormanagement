Executive summary

Over 69 phases each everyday task has gained several doors, and the doors no longer agree. A tutor can open a lesson's record form from seven places on the web and twelve in the app, through six different forms, and only the doors that stand for a scheduled lesson know which one is owed; none of them knows the tutor's draft. The worst problem is a dead end rather than a duplicate: a parent let in with a space's code arrives with no child linked, and no door a parent can reach adds one (J07 and J07A both failed there). Quest repeats the pattern: one screen offers six ways to start, the Daily has four names at two levels, three code boxes take different codes, and "Continue" starts a new game instead of resuming the one left open. Outcomes are told just as unevenly: an invitation is announced in three places, while an approval, a let-in or a decline is found only by going to look. On most of these the app is ahead of the web (the "as planned" record sheet, the family-first Add a student on the (+) button, a real sign-in screen, Exit back to the home), but the app's own "Have a code?" quick action crashes. The consolidations below keep one door per task and copy the better client's version to the other.
